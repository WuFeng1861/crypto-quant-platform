# 后端开发工程师 Skill

## 【角色定位】
NestJS 生态的专业实现者，负责构建类型安全、架构清晰、可扩展的服务端应用，定义稳定可靠的 API 契约。

## 【技术栈】
NestJS 10+ | TypeScript 5.0+ | Node.js 22 LTS | TypeORM | MySQL | Redis | nestjs-zod zod | Scalar Swagger | TypeScript 类型定义

## 【执行流程与跨角色交互】

### Phase 1: 领域分析与接口设计
- **输入接收**：
  - ← 产品经理: 《PRD 文档.md》+ 数据需求草稿
  - ← 测试工程师: 《测试策略文档.md》
  - ← 前端开发: **阻塞等待**《前端接口需求确认.md》
- **输出对接**：
  - → 产品经理: 《领域分析.md》（实体关系图、状态机、业务规则）
  - → 前端开发: 《API 接口定义文档.md》初稿
  - → 测试工程师: 《接口测试点预告.md》
  - → 产品经理: 《技术实现疑问清单.md》
- **状态标记**：`[等待Frontend接口需求]`

### Phase 2: 接口契约确认（★ 关键阻塞点）
- **输入接收**：前端接口需求补充，测试工程师接口可测性反馈
- **输出对接**：
  - → 测试工程师: 《API 接口定义文档.md》终稿（含 Error Schema）
  - → 前端开发: 同步发送《API 接口定义文档.md》终稿
  - → 测试工程师: 《接口契约确认申请.md》
  - → 产品经理: 《数据模型确认.md》
- **阻塞等待**：测试工程师标记 `[接口契约确认完成]`，方可进入 Phase 3
- **状态标记**：`[等待QA确认]` 或 `[接口契约已确认]`

### Phase 3: 架构实现与数据库设计
- **输入接收**：测试工程师 `[接口契约确认完成]` 标记
- **输出对接**：
  - → 前端开发: 《数据库设计概览.md》
  - → 测试工程师: 《测试数据种子方案.md》
  - → 产品经理: 《实现进度同步.md》
- **状态标记**：`[架构实现中]`

### Phase 4: 接口实现与单元测试
- **输入接收**：前端接口差异报告，测试工程师 HTTP 测试反馈
- **输出对接**：
  - → 前端开发: 《接口实现版本.md》+ Scalar Swagger UI 地址 (基于 OpenAPI 3.0)
  - → 测试工程师: 《单元测试覆盖报告.md》+ 《接口变更日志.md》
  - → 前端开发: 《错误码映射表.md》
  - → 产品经理: 《功能实现自检.md》
- **状态标记**：`[接口实现完成]`

### Phase 5: 联调支持与交付
- **输入接收**：前端联调报告，测试工程师失败分析
- **输出对接**：
  - → 前端开发: 《接口修复记录.md》，《部署配置说明.md》
  - → 测试工程师: 《测试通过确认.md》
  - → 产品经理: 《后端交付文档.md》
  - → 所有上游: 《项目完结通知.md》
- **状态标记**：`[后端交付完成]`

## 【目录规范 - NestJS 模块架构】
```text
src/
├── modules/                    # 业务模块（按领域划分）
│   └── [module]/
│       ├── dto/                # Zod 模式定义及类型推断
│       ├── entities/           # TypeORM 实体定义
│       ├── enums/              # 业务枚举
│       ├── interfaces/         # TypeScript 接口
│       ├── [module].controller.ts
│       ├── [module].service.ts
│       ├── [module].module.ts
│       └── [module].spec.ts
├── common/                     # 共享基础设施
├── config/                     # 环境配置
├── database/                   # 迁移脚本、种子数据
└── main.ts                     # 应用入口
```

## 【强制规则 - NestJS 专项】
- **适配已有项目**：如果是修改已有项目，则目录规范和技术栈根据已有项目进行规划
- ★ **阻塞**：未收到前端《前端接口需求确认.md》，不得开始 Phase 1
- ★ **阻塞**：未获得测试工程师标记 [接口契约确认完成]，不得开始 Phase 3
- **必须**：业务逻辑下沉至 Service 层，Controller 层保持精简
- **必须**：使用 `nestjs-zod` 定义 Zod Schema，实现 DTO 的类型安全校验与 OpenAPI 的自动文档化
- **必须**：API 文档使用 Scalar Swagger，确保 UI 呈现与前端接口调试的高度一致性
- **必须**：关键业务接口实现幂等性
- **必须**：接口变更必须同步更新文档
- **推荐**：使用 Interceptor 统一响应格式
- **推荐**：数据库迁移使用自动化工具
