# 批量回测功能版本规划

## 文档信息
- **文档版本**: v1.0
- **创建日期**: 2026-03-15
- **规划周期**: V1.0 - V2.0

---

## 一、版本概览

| 版本 | 目标 | 预计工期 | 核心功能 |
|------|------|----------|----------|
| V1.0 | MVP版本 | 2周 | 批量回测基础功能（串行执行） |
| V1.1 | 增强版 | 1周 | 任务控制优化、筛选功能 |
| V2.0 | 高级版 | 2周 | 并行执行、性能优化 |

## 二、V1.0 - MVP版本

### 2.1 目标
提供可用的批量回测基础功能，支持串行执行和基本的进度跟踪。

### 2.2 功能清单

#### P0 - 必须完成
- [ ] 批量回测任务创建 API
- [ ] 自动获取所有交易对
- [ ] 串行执行批量回测
- [ ] 批量任务状态管理（pending/running/completed/failed）
- [ ] 实时进度查询
- [ ] 批量回测结果汇总
- [ ] 批量回测结果详情列表
- [ ] 数据库表结构创建

#### P1 - 建议完成
- [ ] 指定交易对列表功能
- [ ] 任务取消功能
- [ ] 启动时任务恢复

### 2.3 技术任务分解

| 任务 | 负责人 | 预估工时 | 依赖 |
|------|--------|----------|------|
| 数据库设计（batch_backtests, batch_backtest_items表） | 后端 | 4h | - |
| 实体类创建（TypeORM） | 后端 | 2h | 数据库设计 |
| DTO 定义 | 后端 | 2h | - |
| 批量回测服务核心逻辑 | 后端 | 16h | 实体类、DTO |
| 批量回测 Controller API | 后端 | 4h | 服务逻辑 |
| 进度跟踪实现 | 后端 | 4h | 服务逻辑 |
| 结果汇总查询 | 后端 | 4h | 服务逻辑 |
| 启动恢复功能 | 后端 | 4h | 服务逻辑 |
| 交易对数量限制 | 后端 | 2h | 任务创建 |
| 子任务超时处理 | 后端 | 4h | 执行逻辑 |
| 依赖服务中断处理 | 后端 | 4h | 异常处理 |
| 单元测试 | 后端 | 8h | 全部功能 |
| API 文档更新 | 后端 | 2h | API完成 |

**总计**: 约 60 工时（约 7-8 工作日）

### 2.4 里程碑

| 里程碑 | 日期 | 交付物 |
|--------|------|--------|
| 设计评审 | Day 2 | 数据库设计文档、API设计文档 |
| 开发完成 | Day 6 | 功能代码、单元测试 |
| 测试通过 | Day 8 | 测试报告、Bug修复 |
| 上线发布 | Day 10 | 部署文档、上线确认 |

## 三、V1.1 - 增强版

### 3.1 目标

### 3.2 功能清单

- [ ] 按币种类型筛选交易对

- [ ] 批量任务删除

| 暂停超时处理 | 后端 | 4h | 暂停功能 |
| 重试功能实现 | 后端 | 4h | V1.0 |
| 重试次数限制 | 后端 | 2h | 重试功能 |
| 强制重试接口 | 后端 | 2h | 重试功能 |

| 单元测试 | 后端 | 4h | 全部功能 |

## 四、V2.0 - 高级版

### 4.1 目标
支持并行执行，大幅提升批量回测效率。

### 4.2 功能清单

#### P0 - 必须完成
- [ ] 并行执行框架
- [ ] 可配置并发数
- [ ] 资源限制保护

#### P1 - 建议完成
- [ ] 智能调度（根据系统负载动态调整并发）
- [ ] 分布式执行支持（预留）
- [ ] 执行优先级设置

### 4.3 技术任务分解

| 任务 | 负责人 | 预估工时 | 依赖 |
|------|--------|----------|------|
| 并行执行架构设计 | 后端 | 8h | V1.1 |
| 任务队列实现（Bull/Redis） | 后端 | 8h | 架构设计 |
| 并发控制实现 | 后端 | 8h | 任务队列 |
| 资源监控与保护 | 后端 | 8h | 并发控制 |
| 单元测试 | 后端 | 8h | 全部功能 |

**总计**: 约 40 工时（约 5 工作日）

## 六、发布计划

### 6.1 V1.0 发布检查清单

- [ ] 所有 P0 功能开发完成
- [ ] 单元测试覆盖率 > 80%
- [ ] API 文档更新完成
- [ ] 数据库迁移脚本测试通过
- [ ] 与现有功能兼容性测试通过
- [ ] 性能测试通过（串行执行效率）

### 6.2 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 串行执行时间过长 | 中 | 高 | 提前沟通，引导使用V2.0 |
| 数据库性能瓶颈 | 低 | 中 | 优化批量写入，使用事务 |
| 与现有功能冲突 | 低 | 高 | 充分回归测试 |
